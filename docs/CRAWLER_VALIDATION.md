# 爬虫内容验证功能说明

## 修改时间
2026-01-28

## 问题描述
之前爬虫服务在爬取失败时，仍然会将错误的空内容保存到数据库，导致：
1. 数据库中存储了无效数据（title=null, content=null等）
2. 后续请求会从数据库读取这些无效数据，继续走审核流程
3. 浪费AI审核资源，影响用户体验

## 解决方案

### 1. 新增内容验证函数
在 `CrawlerService` 中添加 `validateCrawledContent()` 方法：

**验证规则：**
- PostID不能为空
- URL不能为空
- 至少要有以下之一：
  - 标题（title）
  - 正文（content）
  - 图片（images）

**验证失败处理：**
- 记录详细的错误日志
- 抛出 `RuntimeException`，阻止保存到数据库
- 提示用户爬取失败原因

### 2. 爬取流程改进
```
原流程：爬取 → 保存数据库 → 缓存Redis
新流程：爬取 → 验证内容 → 保存数据库 → 缓存Redis
                    ↓（失败）
                抛出异常，不保存
```

### 3. 缓存读取改进
从数据库读取缓存时，也会进行内容验证：
- 如果内容有效：正常返回
- 如果内容无效：
  1. 从数据库删除无效数据
  2. 重新执行爬虫
  3. 验证新内容后保存

### 4. 错误提示优化
在 `ContentAuditService` 中改进异常处理：
- 区分URL验证失败、爬取失败、审核失败
- 提供更友好的错误提示信息
- 建议用户检查链接有效性或稍后重试

## 代码修改位置

### CrawlerService.java
1. `crawlContent()` 方法：
   - 爬取后添加验证
   - 数据库缓存命中时也验证

2. 新增 `validateCrawledContent()` 方法：
   - 验证必填字段
   - 验证核心内容
   - 记录验证日志

### ContentAuditService.java
1. `auditContent()` 方法：
   - 改进异常捕获逻辑
   - 区分不同错误类型
   - 提供更详细的错误信息

## 使用效果

### 爬取成功示例
```
[爬虫服务] 内容验证通过: postId=xxx, hasTitle=true, hasContent=true, hasImages=true
```

### 爬取失败示例
```
[爬虫服务] 内容验证失败: postId=xxx, errors=爬取内容为空：没有标题、正文或图片
抛出异常: RuntimeException: 爬取内容验证失败: 爬取内容为空：没有标题、正文或图片
```

### 缓存无效数据清理
```
[爬虫服务] PostgreSQL缓存内容无效，删除并重新爬取: postId=xxx, error=爬取内容为空：没有标题、正文或图片
```

## 测试建议

1. **测试无效链接**：使用不存在的链接测试验证逻辑
2. **测试有效链接**：确保正常爬取不受影响
3. **测试数据清理**：验证无效缓存数据能被正确删除和重新爬取
4. **测试错误提示**：检查用户收到的错误信息是否清晰

## 后续优化建议

1. 添加爬取失败计数器，避免无限重试
2. 为频繁失败的URL添加黑名单机制
3. 增加更多维度的内容质量验证（如最小内容长度）
4. 添加爬取成功率监控指标
